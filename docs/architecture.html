Data flow

Step by step

  1. Planned Apple Watch

    The watch measures heart-rate variability (HRV) on the wrist. Raw samples stay on the watch and phone.

  2. Planned iPhone · HealthKit

    A companion app on the iPhone would read HRV through HealthKit and compute how far today is from your own baseline. HealthKit is an on-device Apple framework, not a remote API: the app reads it locally with your permission, and nothing leaves the phone unless the app sends it.

  3. Planned Send the summary only

    Only the preprocessed result is sent: for example the deviation from baseline and the minutes in the current session. Raw HRV is not sent. It would be opt-in and can be switched off.

  4. Implemented in this prototype Conversation signals

    The conversation page reads only what the chat itself shows: reply length, short replies, repeated questions, pauses and explicit requests such as “shorter, please”. No microphone, camera or sensor is used. A separate JavaScript module (partner.js) turns these signals into a calm, optional adjustment that can be undone. It runs next to the density engine and feeds it, and it works with or without an HRV summary.

  5. Implemented in this prototype Loop escape (rules)

    Reads a conversation you paste (or a simulated one) and looks for four patterns: the same question again, the AI repeating itself, long with no progress, changing direction. It uses word overlap and wording patterns in English and Korean, no network and no embeddings API. If it finds one, it offers a single suggestion with the reasons, waits about 20 minutes before the next one and can be undone. A rising load makes it go first. It is a rough rule-based check, not a verdict.

  6. Implemented in this prototype Density engine

    The density engine combines your profile with that summary and picks the amount, pace and shape of the answer. In this prototype it is rule-based JavaScript running in your browser. Later it could run next to a cloud AI or as a light on-device model.

  7. Implemented in this prototype Fitted answer

    The answer is reshaped to the chosen settings. In this prototype a rule-based transform does it, and an adapter interface lets a developer plug in a model.

  8. Implemented in this prototype Virtual HRV slider

    The demo and landing page use a slider that stands in for the first three steps. No sensor is read and no value is real.

  9. Planned Loop: LLM judgment, extension, real chat

    Planned, not built: a language-model check of whether the conversation is really stuck, a browser extension that watches a chat page, and integration with real chat products. Until then, loop detection only runs on text you paste into the demo.

  10. Planned MCP tool

    Exposing the engine as an MCP (Model Context Protocol) tool is a possible later step, only after the idea has been validated. Not built.

Summary format (sample)

This is the small summary the engine reads. In this prototype the values are virtual. The same shape is used by the demo sliders. Files: docs/data/sample-hrv.json and docs/data/hrv-summary.schema.json.

{
  "schema": "attune.condition.v1",
  "source": "virtual",
  "baselineHrvMs": 55,
  "hrvMs": 37,
  "sessionMinutes": 20
}

baselineHrvMs: your usual HRV in ms. hrvMs: today. sessionMinutes: time in the current AI session. source must be "virtual" in this prototype.
